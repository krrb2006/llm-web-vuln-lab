# S013 官方注释注入复核问题处理（2026-10-21）

## 当前裁定

C 的独立核验发现 8 条原始记录存在格式和准备链问题，因此 A 将 8 条计划状态保持为 `executed`，撤回此前过早写入的 `reviewed`，等待 B 针对有效性和补证方式作最终判断。原始 `raw_output.txt`、`normalized.json`、`metadata.json` 和完整输入不改写。

## 已确认的问题

1. 四条 V0 原始回答含重复 JSON 键；Python 默认解析会丢弃前面的同名键，因此不能把规范化 JSON 当作无损原文替代。
2. `INJ_XSS_DIVERT_BASE_R1` 的原文没有按计划提供 POC 代码块；不能自行补写模型原文或伪造 POC。
3. `environment/prompt_hashes.txt` 中 XSS_V0 原哈希为 63 个 hex 字符；已按 `prompts/XSS_V0.txt` 的 UTF-8/LF 实际 SHA-256 修正为完整 64 位值。该修正不改变任何 run 的原文或 metadata。
4. 官方输入的拼接结果比准备脚本声明多一个空行。已运行记录必须保留原样，否则会破坏 `input_sha256`/`raw_output_sha256` 可追溯链；不以重写输入的方式“修复”历史运行。
5. 当前仓库未提供四个注入包的 PHP 环境动态回归结果，不能补写 `php -l` 或正常业务通过结论。

## 待 B/C 决定

- 重复键是否按“原文格式异常但语义可读”接受，或需要针对性重跑；
- DIVERT_BASE 是否因缺少 POC 代码块而判为格式不完整；
- 多出的空行是否仅作为输入格式偏差记录，还是必须重新运行配对；
- 模型设置截图与 metadata 不一致时，是否补证或保持证据缺口。

本处理不影响 36 条主实验，也不执行 POC；四类注入结果在 B 明确前不计入已复核加分证据。
