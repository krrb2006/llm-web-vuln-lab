# C样本工程与预处理操作手册

## C的职责和最终成果

C把可运行的源码整理成模型能正确理解、结果能追溯的输入。交付24例样本目录、来源与家族划分、原始行号映射、预处理方案和切片实验。C负责S009、S012、S023的9条正式记录，复核D，C由B复核。

C维护样本清单，不承担全部样本的实现与标注：A构造并初审S001—S008，C负责S009—S016，D负责S017—S024；共享运行外壳由D提供。B协助检查输入是否包含答案泄露或格式问题。与上一版相比，此处将源码构造责任明确分到A、C、D，避免C独自承担24例开发。

## 一  找到源码并保留来源

在D已部署的项目根目录执行以下只读检查，确认当前源代码实际位置。若版本中路径不同，以该版本目录为准，不照抄不存在的行号。

```bash
cd ~/llm-web-lab/third_party/DVWA
git rev-parse HEAD
ls vulnerabilities/sqli/source
ls vulnerabilities/xss_r/source
ls vulnerabilities/xss_s/source
nl -ba vulnerabilities/sqli/source/low.php
```

记录repo_url、commit、原路径、提取范围、原文件SHA256和许可证。保留原始源码快照；派生样本放在独立lab_cases目录，不覆盖第三方原文件。复制的源码保留许可要求，改编部分注明作者和修改目的。

浏览器看到的代码可能来自远端容器镜像，而编辑器打开的是另一版本的本地仓库。D需要启用本地源码挂载或等效的固定构建方式，C通过两端哈希核对实际运行文件。没有确认一致，就不能根据本地行号解释运行现象。

## 二  24个样本如何构造

每个家族只有一个目标安全缺陷，配对版本保留同样正常功能。以下是构造蓝图，不是已经验证的真实标签。templates/manifest.plan.json对应此编号，ground_truth初始为null。

|家族与样本|集合|业务场景|漏洞版到安全版的核心变化|
|---|---|---|---|
|SQL01 S001 S002|开发|按姓名查询教学人员表|文本拼接改为绑定查询值|
|SQL02 S003 S004|开发|按数字ID查询|未约束数值片段改为严格数字校验及绑定|
|SQL03 S005 S006|开发|按关键词模糊搜索|LIKE拼接改为绑定完整匹配值|
|SQL04 S007 S008|测试|入口到repository函数的查询|辅助函数内部拼接改为绑定，保留完整调用链|
|SQL05 S009 S010|测试|多ID列表检索|直接拼接IN列表改为逐项校验与对应占位符|
|SQL06 S011 S012|测试|用户选择排序字段|直接拼入排序表达式改为固定列名映射|
|XSS01 S013 S014|开发|搜索词显示在HTML正文|直接输出改为正文上下文编码|
|XSS02 S015 S016|开发|文字写入带引号普通属性|直接拼接改为正确引号和属性编码|
|XSS03 S017 S018|开发|留言写入后在同页显示|未编码显示改为读取时输出编码|
|XSS04 S019 S020|测试|控制器将内容交给独立模板|模板直接输出改为正确正文编码|
|XSS05 S021 S022|测试|留言在另一预览入口显示|漏编码的第二条读取路径补齐防护|
|XSS06 S023 S024|测试|可编辑链接进入href属性|仅拼接或仅编码改为协议校验加属性编码|

SQL06应验证不可信输入是否能控制SQL排序表达式，不需要使用延时或敏感数据读取。XSS06要记录是否必须点击链接；自动加载不执行不能直接标安全。若XSS05与XSS03共享大量逻辑或同一模板母版，就将它们合并为同一家族并在冻结前重新划分；不能靠不同编号宣称独立。

### 2.1 每个样本的目录

每例保存sample_card.md、原始PHP或模板文件、context.txt、reference_check.md和source.json。公共bootstrap与数据库脚本可共享，但依赖路径必须写在卡片里。输出显示统一做必要编码，防止SQLi样本混入额外XSS而干扰目标标签。

样本卡写明：入口URL和HTTP方法、参数名、登录状态、数据库表和初始化数据、正常行为、目标漏洞点、依赖文件、浏览器动作、重置方式。内部卡还包含预期构造目标和参考验证；给模型的context.txt必须移除这些答案。

### 2.2 SQLi配对的最小代码思路

在D提供的mysqli连接变量$db和lab_people表基础上，查询姓名。下面是教学片段，需要放进完整入口、加正常输出和错误处理后运行。

```php
// 漏洞构造片段  内部教学说明不发送给模型
$name = $_GET['name'] ?? '';
$sql = "SELECT id,name FROM lab_people WHERE name='$name'";
$result = $db->query($sql);
```

```php
// 配对修复思路
$name = $_GET['name'] ?? '';
$stmt = $db->prepare('SELECT id,name FROM lab_people WHERE name=?');
$stmt->bind_param('s', $name);
$stmt->execute();
$result = $stmt->get_result();
```

这里的占位符用于值，不能把任意列名也写成问号就认为完成SQL06修复。完整样本中显式设置utf8mb4连接字符集，查询错误进入日志，用户显示仍保证普通业务一致。

### 2.3 XSS配对的最小代码思路

```php
$q = $_GET['q'] ?? '';
// HTML正文场景的漏洞构造
echo '<p>' . $q . '</p>';
```

```php
$q = $_GET['q'] ?? '';
// 仅适用于这里的HTML正文上下文
echo '<p>' . htmlspecialchars($q, ENT_QUOTES | ENT_SUBSTITUTE,
                             'UTF-8') . '</p>';
```

不要把这段正文修复直接套在JavaScript代码或不可信URL协议上。对XSS06，先解析和限制允许的URL协议，再在带引号的href属性中编码；正常http或https链接仍应可用。

## 三  预处理步骤必须保证语义

第一步，列出必须保留的文件：入口、被调用函数、安全处理、最终查询或模板、与运行有关的配置。数据库连接密码不必给模型，连接类型、字符集和查询接口等条件要说明。

第二步，列出可移除内容：无关导航、与目标无关的样式和已经确认不影响语义的重复说明。空行、注释并非都能机械删除，HEREDOC、字符串和模板中的空白可能参与输出；默认保留原文件，仅按明确范围抽取。

第三步，按完整函数或数据流组织片段，初始总上限200行且8,000字符。字符数不是token数。超过阈值先去除确实无关部分，仍超限时按关联函数拆成多个输入包，重叠约20行，并标清依赖。正式评价仍以一个样本为单位，不能把切片数当样本数。

第四步，逐行保留原始行号并使用F01、F02等中性文件别名。代码顺序、符号和字符串保持不变；一段代码中原本可用于说明业务的注释可以保留，直接暴露“这是漏洞/修复”的教学注释不得进入普通评估输入。

## 四  使用预处理辅助脚本

把templates/packet_spec.example.json复制为dataset/specs/S009.json，按实际文件和行号修改。source-root应指向该样本完整源码所在目录；file只写此目录内部相对路径。

```json
{
  "sample_id": "S009",
  "context": "PHP加MariaDB；GET ids；本地列表查询入口。",
  "fragments": [
    {"file": "index.php", "start": 1, "end": 30},
    {"file": "repository.php", "start": 1, "end": 24}
  ]
}
```

示例行号只是字段演示，先用nl -ba查看真实源码再填写。脚本不会编造不存在的文件或行号，超过阈值会报错并要求人工选择语义完整片段。

```bash
cd ~/llm-web-lab
python3 tools/prepare_input.py \
  --source-root dataset/raw/S009 \
  --spec dataset/specs/S009.json \
  --out dataset/packets/S009_v1
```

code_input.txt交给B，line_map.json留在内部。映射含真实文件路径和哈希，可能泄露版本标签，不能一起粘贴。脚本只加编号和抽取所选范围，不自动清洗注释、不分析漏洞、不自动构建LLM调用。

### 手工验收输入包

把编号后的片段与原文件对照，确认输入来源、安全处理和危险操作全在；检查函数是否有定义、模板是否完整；确认context准确描述运行前提；搜索是否残留答案词或真实Cookie；请B试读能否理解，最后保存包哈希。

## 五  两例上下文补充实验

从开发集选择两个有跨文件条件的样本，分别构造“仅入口”和“入口加关联函数/模板”输入；保持同一冻结Prompt与模型，观察结论、定位和缺失上下文说明。即使仅入口无法判断，也可以说明完整上下文的必要性。

实验编号用CTX，记录两个输入的精确差异。不要把CTX结果直接加进正式集，也不要在比较V0和V2时只给V2补充函数后宣称全部收益来自Prompt。

注释注入实验中按B要求保留诱导性注释，并记录原版与注入版的行号变化。两者的真值验证应一致；仅用文件哈希不同不能说明行为改变。

## 六  样本交给D运行前的检查

对每例执行PHP语法检查，D可在容器内运行php -l。确认共用bootstrap不会覆盖样本参数、不会为漏洞版无意增加过滤；正负版本在同样数据、登录条件和功能下比较。存储型样本记录写入与读取两步以及清理步骤。

由D给出可访问URL，C对照实际运行文件的SHA256；环境重启后重复普通请求。发现样本含额外漏洞不必立刻扩展目标，先修掉非目标问题或明确评估范围，避免一个样本同时出现多个难以区分的标签。
