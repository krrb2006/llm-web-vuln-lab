## 三、逐例审核

### 通用检查（六例全部通过）

1. **行号/字节/片段完整性**：每份 `code_input.txt` 的 `F01` 编号行与 A `26637fb` 的 `index.php` 逐行对照，行号连续、字节一致，片段覆盖全文件（S001 1–24、S002 1–27、S003 1–24、S004 1–34、S005 1–24、S006 1–29）。
2. **source_commit**：六份 `draft_metadata.json` 的 `source_commit` 均为 `26637fb325905e00ad0466c22386d4f78771cc0c`，与 A 当前提交一致。
3. **D 三项上下文要求**：
   - 无过时状态句：六份 context 均无「尚待 D 核验」等旧表述，干净；
   - 有入口 URL：S001/S002 使用 `name`、S003/S004 使用 `id`、S005/S006 使用 `q`，URL 形如 `http://127.0.0.1:4280/lab_cases/S00x/index.php`；
   - S005/S006 LIKE：B 草稿已含「SQL LIKE 模式中的 % 与 _ 仍具有匹配通配符语义」，缺后半句；本审核已补「其匹配范围变化本身不作为 SQL 注入证据」（见下）。
4. **公共文件**：`common/db_connect.php` 不入片段，仅在 context 说明 `$db` 为已连接的 mysqli 变量、表字符集 utf8mb4，符合要求。

### S005（SQL03，vulnerable，修订）
- 代码：`q` 直接拼接进 `LIKE '%...%'`（`index.php:10`），`$db->query` 执行；无 prepare/bind（符合构造目标）。

### S006（SQL03，fixed，修订）
- 代码：`%q%` 模式经 `prepare`/`bind_param('s')` 绑定（`index.php:12–13`），安全处理完整。
- 上下文修订：同 S005，补「其匹配范围变化本身不作为 SQL 注入证据」。
