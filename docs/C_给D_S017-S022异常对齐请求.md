当前 S017/S018/S021/S022 的 mysqli `prepare/bind_param/execute/get_result/fetch/close` 全部是裸调用、无 try/catch，在 PHP 8.5 严格模式下抛 `mysqli_sql_exception` 时会直接中断页面（Fatal error 或未捕获异常），不符合统一口径，需对齐。

## 三、对齐目标

1. 每个样本的**写入段**（INSERT）和**读取段**（SELECT）整体套入 `try { ... } catch (Throwable $e) { error_log(...); }`。
2. 异常分支仅写 `error_log()`，页面回落为普通提示或空结果；不向页面回显 `$e->getMessage()`，不设 `MYSQLI_REPORT_OFF`，不降级 mysqli 严格模式。
3. `$db->insert_id`（submit.php:20）必须与 `execute()` 同处 try 块内，保证成功后读取自增 ID。
4. 读取失败时 `$messages`/`$drafts`/`$draft` 回落到空数组或 null，让页面按「无数据 / 不存在」正常分支继续渲染，避免 foreach/fetch 未定义变量。
5. 对齐后 C 会重算各文件 SHA256 并更新 source.json / manifest 的 `case_code_sha256`（`ground_truth` 仍保持 null）。
