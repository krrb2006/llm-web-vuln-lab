## 标准化前需修订

1. 六份 `runtime_context` 都写着“实际容器运行和数据库初始化尚待 D 核验”。D 的环境记录现已包含 S001–S012 的 HTTP 参考观察，因此这句话已过时，应删除或改为当前已核实的中性环境事实。
2. 六份上下文没有给出具体本机路径。V0 草稿要求 POC 不得臆造路径，所以 C 的标准包应提供对应 GET 入口，例如 `http://127.0.0.1:4280/lab_cases/S001/index.php?name=...`；S003/S004 使用 `id`，S005/S006 使用 `q`。若标准 Prompt 不要求可运行 POC，也应由 B 明确该字段如何处理。
3. S005/S006 应用中性描述说明 LIKE 的 `%` 和 `_` 仍是匹配通配符，其匹配范围变化本身不作为 SQL 语法注入证据。A 的样本卡已经区分此行为与受控真假条件。
4. C 标准化后，应在 `dataset/packets/` 生成正式 `code_input.txt` 与内部行号映射，再由 C 确认包哈希。B 的 `results/B_proposed_packets/` 目前仍是草稿；C 确认前，不应把这些草稿当作冻结输入提交给 DeepSeek。
