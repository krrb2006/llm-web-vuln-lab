# LLM 辅助 Web 漏洞挖掘与验证代码说明

## 一 项目用途

本项目用于网络安全课程实验，演示如何使用大语言模型辅助进行 SQL 注入（SQLi）和跨站脚本（XSS）代码审计，并通过人工复核、本地教学靶场和受控 POC 验证模型结论。

所有动态验证仅面向本机 `127.0.0.1:4280` 的授权教学环境，不用于扫描或攻击公网系统。

## 四 最小测试流程

在仓库根目录执行。Windows PowerShell 使用 `python`；Linux/macOS/WSL 可将其替换为 `python3`。

### 1 安装基础环境

需要 Git、Python 3.10 以上和 Docker Desktop。仅运行静态检查和单元测试时不需要启动 Docker。

```powershell
python --version
git --version
docker version
docker compose version
```

### 2 运行项目检查

```powershell
python -m unittest discover -s tests -v
python tools/check_freeze.py --report-only
python tools/audit_submission.py
```

预期结果：项目测试 `22/22` 通过，冻结检查显示 `READY`，提交审计显示正式数据集、运行记录和加分实验的证据状态为 `READY`。

这些检查只读仓库文件，不调用模型、不部署靶场、不执行 POC。

### 3 阅读实验结果

建议按以下顺序阅读：

1. `docs/最终实验报告_2026-10-26.md`
2. `docs/00_总执行手册.md`
3. `results/formal_eval_2026-10-19-v2/summary.md`
4. `results/evidence_index_2026-10-21.md`

正式实验为 12 个测试样本分别使用 V0、V1、V2 Prompt，共 36 条记录；加分实验包括 16 条 Prompt Injection、2 条 Burp 联动、4 条上下文消融和 4 条高级案例。

### 4 可选启动本地教学靶场

首次使用时，按 `environment/README.md` 准备 DVWA：

```powershell
git clone https://github.com/digininja/DVWA.git third_party/DVWA
$aRef = 'd498903da01d89a695fa49d5392d3776eb901e2f'
$cRef = '8da63f7b8e169e5037626b0362d005ba7ba5ede0'
$dRef = 'a296e4b527ebdaf41ca04c2bbc5627b1a89efc06'
python environment/build_lab_cases.py --a-ref $aRef --c-ref $cRef --d-ref $dRef
python environment/init_lab_db.py
docker compose --env-file local/lab.env -f third_party/DVWA/compose.yml -f environment/compose.lab.yml up -d
```

浏览器访问 <http://127.0.0.1:4280/>。可用以下命令检查运行环境：

```powershell
python environment/check_runtime.py --a-ref $aRef --c-ref $cRef --d-ref $dRef
python environment/check_sql_http.py --sample S009 --sample S010
python environment/check_xss_browser.py
python environment/check_d_business.py
```

验证结束后停止服务：

```powershell
docker compose --env-file local/lab.env -f third_party/DVWA/compose.yml -f environment/compose.lab.yml down
```

不要把 `local/lab.env`、登录 Cookie、令牌或未脱敏截图提交到仓库。不要使用 `docker compose down -v`，以免删除 DVWA 数据卷。

## 五 如何复核一个样本

1. 在 `dataset/manifest.json` 中找到样本编号和真值记录。
2. 在 `dataset/raw/<sample_id>/` 阅读原始 PHP、样本卡和真值复核说明。
3. 在 `dataset/packets/` 查看发送给模型的固定输入和 `line_map.json`。
4. 在 `runs/F_<sample>_<version>_R1/` 查看模型原文、规范化 JSON、输入哈希和运行元数据。
5. 在 `pocs/` 和 `evidence/` 查看 POC 及其本地验证证据。
6. 对照 `results/` 中的复核记录，区分模型预测、代码定位、原始 POC 可执行和实际漏洞触发，不把其中任何单项单独当作漏洞成立证明。

## 六 安全边界

- 只在授权的本地教学靶场运行动态请求。
- 不将 HTTP 200、脚本退出码 0 或模型回答单独作为漏洞触发证据。
- 原始 POC、环境适配 POC 和逻辑修改版 POC 分开记录。
- 正式统计只使用冻结后的 36 条记录；加分实验不回写主实验指标。
- 本项目结果只代表本组小规模、受控教学样本，不外推为真实世界漏洞发现率。
