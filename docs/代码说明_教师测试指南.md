# LLM 辅助 Web 漏洞挖掘与验证代码说明

## 一 项目用途

本项目用于网络安全课程实验，演示如何使用大语言模型辅助进行 SQL 注入（SQLi）和跨站脚本（XSS）代码审计，并通过人工复核、本地教学靶场和受控 POC 验证模型结论。

所有动态验证仅面向本机 `127.0.0.1:4280` 的授权教学环境，不用于扫描或攻击公网系统。

这些检查只读仓库文件，不调用模型、不部署靶场、不执行 POC。

## 六 如何复核一个样本

1. 在 `dataset/manifest.json` 中找到样本编号和真值记录。
2. 在 `dataset/raw/<sample_id>/` 阅读原始 PHP、样本卡和真值复核说明。
3. 在 `dataset/packets/` 查看发送给模型的固定输入和 `line_map.json`。
4. 在 `runs/F_<sample>_<version>_R1/` 查看模型原文、规范化 JSON、输入哈希和运行元数据。
5. 在 `pocs/` 和 `evidence/` 查看 POC 及其本地验证证据。
6. 对照 `results/` 中的复核记录，区分模型预测、代码定位、原始 POC 可执行和实际漏洞触发，不把其中任何单项单独当作漏洞成立证明。

## 七 安全边界

- 只在授权的本地教学靶场运行动态请求。
- 不将 HTTP 200、脚本退出码 0 或模型回答单独作为漏洞触发证据。
- 原始 POC、环境适配 POC 和逻辑修改版 POC 分开记录。
- 正式统计只使用冻结后的 36 条记录；加分实验不回写主实验指标。
- 本项目结果只代表本组小规模、受控教学样本，不外推为真实世界漏洞发现率。

## 八 Web 应用代码说明

仓库中的 `web/` 是在实验数据集基础上实现的可自托管代码审计 Web 应用。它不是另一个实验数据集，而是把“静态规则定位 + 可选 LLM 复核 + 人工复核”做成可操作的界面。

### 8.1 技术结构

```text
浏览器
  │
  ├── 原生模式：FastAPI 同时托管 web/static/，SQLite 保存本地数据
  │
  └── Docker 模式：nginx（前端与网关） → FastAPI → MySQL
                              │
                              └── 解压、过滤、数据流分析、规则扫描、LLM 复核
```

| 层 | 主要文件 | 作用 |
|---|---|---|
| React 前端 | `web/frontend/src/` | 登录、注册、上传、模型配置、任务列表、发现详情和报告下载 |
| 前端构建 | `web/frontend/package.json`、`vite.config.ts` | TypeScript 类型检查和 Vite 生产构建 |
| FastAPI 入口 | `web/backend/app/main.py` | 建表、演示账号、健康检查、原生模式 SPA 托管 |
| 认证接口 | `web/backend/app/routers/auth.py`、`security.py` | 注册、登录、JWT 校验 |
| 任务接口 | `web/backend/app/routers/jobs.py` | 上传、示例任务、任务列表、详情、删除和 Markdown 导出 |
| 解压安全 | `web/backend/app/services/archive.py` | 路径穿越校验、符号链接过滤、文件类型和大小限制 |
| 静态分析 | `web/backend/app/services/scan.py`、`dataflow.py` | 规则扫描和 PHP/JS/TS/Python 数据流分析 |
| 模型复核 | `web/backend/app/services/llm.py` | 调用 OpenAI 兼容接口并规范化 JSON 结果 |
| 任务编排 | `web/backend/app/services/pipeline.py` | 解压、扫描、复核、统计和结果持久化 |
| Docker 网关 | `web/nginx/`、`docker-compose.yml` | nginx 静态托管、`/api` 反向代理、MySQL 编排 |
| 原生启动 | `web/scripts/run-native.ps1`、`run-native.sh` | 无 Docker 的本地 SQLite 运行方式 |

### 8.2 一键本地部署

Windows 新用户可以双击 `web/start-web.cmd`。命令行方式为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File web/scripts/run-native.ps1
```

该脚本会检查 Python、创建 `web/.venv-native`、检查并补装 `fastapi`、`sqlalchemy`、`uvicorn` 等依赖，设置本地数据目录和随机 JWT 密钥，然后启动 `127.0.0.1:8081`。

Linux、macOS 和 WSL 使用：

```bash
bash web/scripts/quickstart.sh
```

原生模式的数据库文件为 `web/data/vulnlab.db`，不需要 MySQL 或 Docker。若要让同一局域网的同学访问：

```powershell
powershell -File web/scripts/run-native.ps1 -Bind 0.0.0.0
powershell -File web/scripts/show-url.ps1
```

Docker 模式用于复现“React + FastAPI + MySQL + nginx”完整架构：

```bash
cd web
cp .env.example .env
# 修改 MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD、JWT_SECRET
docker compose up -d --build
```

启动后访问 `http://localhost:8080`。健康检查接口为 `/api/health`，返回 `status=ok` 且 `database=ok` 表示后端和数据库均已就绪。

### 8.3 教师演示路径

1. 打开 `http://127.0.0.1:8081`（原生模式）或 `http://localhost:8080`（Docker 模式）。
2. 使用演示账号 `demo@vulnlab.local / demo-vulnlab-2026` 登录；也可以在登录页注册新账号。
3. 点击“用示例仓库试一下”，验证任务创建、状态轮询和发现详情；若上传卡片已填写 API Key，该示例任务也会执行 LLM 复核。
4. 在任务详情页查看严重度、文件路径、行号、代码片段、数据流路径、分析和修复建议。
5. 点击“导出报告”下载 Markdown 报告。
6. 在设置页填写自己的 OpenAI 兼容 API Key，再上传有权审计的源码包，观察 LLM 复核结果。
7. 测试结束后清除浏览器中的 API Key，并执行 `docker compose down` 或关闭原生启动终端。

任务详情页会同时显示“静态候选数”和“实际模型调用次数”。如果填写了 API Key 但静态扫描没有候选，调用次数显示为 0，这是当前设计：系统不会把没有静态证据的整仓源码直接发送给模型；只有命中的前若干条候选会进入 LLM 复核。若候选数大于 0 但调用次数仍为 0，应查看任务错误信息中的模型地址、Key、网络或响应格式问题。

### 8.5 Web 应用安全边界与已知不足

- 上传代码只被解压和读取，不执行用户上传的 PHP、JavaScript、Python 或其他程序。
- API Key 不写入 MySQL，但会在单次请求中经过后端；公网部署必须使用 HTTPS，并只连接信任的实例。
- 前端当前将 JWT 和模型配置保存在浏览器 `localStorage`，没有邮箱验证、找回密码、2FA、OAuth/SSO 和组织权限。
- 任务使用 FastAPI `BackgroundTasks`，服务重启时运行中的任务不会自动恢复，不适合直接横向扩展。
- 当前只能上传源码包，暂不支持直接填写 GitHub 地址、分支选择、增量扫描、CI 阻断和 SARIF 回写。
- 分析是启发式辅助，LLM 结论可能误报或漏报；没有自动执行 POC、依赖漏洞比对或真实业务语义验证。
- 原生模式用 SQLite，Docker 模式用 MySQL；两种模式的数据不自动互通。

完整限制、使用建议和后续优先级见 [`web/docs/FRONTEND_LIMITATIONS.md`](../web/docs/FRONTEND_LIMITATIONS.md)。

## 九 Web 部署故障排查

### 9.1 `pydantic-core` 编译失败

如果安装日志出现：

```text
Failed building wheel for pydantic-core
failed-wheel-build-for-install
```

这表示 `pip` 没有找到适配当前 Python 的预编译 Wheel，转而尝试编译 Pydantic 的 Rust 扩展。它通常由 Python 版本过新、32 位 Python、非 x64 架构或 PyPI 镜像不完整导致，不是 Web 业务代码错误。

教师和组员应统一使用 **64 位 Python 3.11 或 3.12**。检查环境：

```cmd
python --version
python -c "import platform,struct; print(platform.machine()); print(struct.calcsize('P')*8)"
```

若虚拟环境已经安装失败，删除后使用 Python 3.11 重建：

```cmd
cd /d "D:\\仓库路径\\llm-web-vuln-lab\\web"
rmdir /s /q .venv-native
py -3.11 -m venv .venv-native
.venv-native\Scripts\python.exe -m pip install --upgrade pip
.venv-native\Scripts\python.exe -m pip install -r backend\requirements.txt -i https://pypi.org/simple
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run-native.ps1 -NoBrowser
```

如果官方源访问慢，可将安装源替换为 `https://pypi.tuna.tsinghua.edu.cn/simple`。不建议为了课程演示先安装 Rust 编译器；统一 Python 版本和使用预编译 Wheel 更容易复现。

### 9.2 其他常见故障

| 错误或现象 | 判断 | 解决办法 |
|---|---|---|
| `-File scripts/run-native.ps1 不存在` | Windows CMD 没有真正切换到 D 盘 | 使用 `cd /d` 或传脚本绝对路径 |
| `No module named uvicorn` | 虚拟环境创建了但依赖未完成 | 重新运行启动脚本，必要时删除 `.venv-native` |
| `ERR_CONNECTION_REFUSED` | Uvicorn 已退出或启动窗口关闭 | 保持启动窗口，检查 `curl.exe http://127.0.0.1:8081/api/health` |
| `Invoke-WebRequest 不是内部或外部命令` | PowerShell 命令被放在 CMD 执行 | CMD 使用 `curl.exe`，PowerShell 才使用 `Invoke-WebRequest` |
| `端口已被占用` | 8081/8080 被其他程序使用 | 原生模式使用 `-Port 8082`，Docker 修改 `HTTP_PORT` |
| Docker 镜像或 pip 下载超时 | 外部网络、校园网或代理限制 | 更换网络/镜像源，或先运行原生模式 |
| 页面打开但 502/503 | FastAPI/MySQL 尚未完成启动 | 等 `/api/health` 返回 `status=ok` 再刷新 |
| 局域网同学访问失败 | 只监听本机或防火墙阻断 | 使用 `-Bind 0.0.0.0` 并放行 TCP 8081 |
| API Key 调用失败 | Key、Base URL 或模型名不匹配 | 先测试无 Key 静态扫描，再核对 OpenAI 兼容配置 |
| GitHub Pages 没有登录/API | Pages 仅支持静态文件 | 使用原生模式或 Docker；FastAPI/MySQL 不会在 Pages 上运行 |

## 十 提交压缩包说明

提交给老师的压缩包应包含源码、实验数据、报告、测试说明和 `web/` 应用，但不应包含：

解压提交包后，老师可先执行根目录静态检查，再进入 `web/` 按本说明的原生模式启动。需要复现 MySQL/nginx 架构时，再执行 Docker 模式。网络不稳定时，依赖安装和 Docker 镜像拉取可能失败，这属于外部网络条件，不代表源码测试失败。
