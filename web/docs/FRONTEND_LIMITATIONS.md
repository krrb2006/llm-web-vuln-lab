# 前端当前限制与使用边界

这份文档把当前 Web 前端的“能做什么”和“还没有做什么”写清楚，避免把实验型工具误认为完整的商业 SAST 平台。

## 当前版本的限制

### 1. 输入方式仍然是手动上传

- 当前只能上传 `.zip`、`.tar.gz`、`.tgz`、`.tar.bz2`、`.tar.xz` 或单个源码文件。
- 不能直接填写 GitHub/GitLab 仓库地址，也没有 OAuth 授权后自动拉取仓库的功能。
- 默认单次上传上限为 20 MiB、3000 个文件；单文件和压缩包条目也有限制。
- `node_modules`、`vendor`、`.git`、构建产物等目录会被跳过，因此依赖库中的问题不会被完整分析。

### 2. 分析结果是辅助结论，不是漏洞证明

- 静态数据流和正则规则都是启发式实现，可能漏报或误报。
- LLM 复核依赖用户填写的 OpenAI 兼容接口；模型不可用、返回格式不规范或网络超时都会使该条回退为静态候选。
- 当前没有自动执行 POC、浏览器验证、依赖版本比对或真实业务语义验证。
- 报告中的“漏洞成立”必须由人工结合源码、请求和授权环境再次确认。

### 3. 交互和可视化仍偏工作台原型

- 分析进度通过轮询刷新，不是 WebSocket/SSE 实时流式更新；任务多或网络慢时会有延迟。
- 详情页提供代码片段和行号，但没有完整源码浏览器、跨文件跳转、差异视图或语法高亮编辑器。
- 报告目前主要导出 Markdown，没有 PDF、SARIF、CSV 或直接创建 GitHub Issue 的功能。
- 没有任务取消、暂停、重试和批量删除操作。

### 4. 账号与密钥管理不是企业级实现

- JWT 令牌和模型配置保存在浏览器 `localStorage`；共享电脑或遭遇 XSS 时需要手动退出并清除浏览器数据。
- 没有邮箱验证、找回密码、双因素认证、OAuth/企业 SSO、组织/项目级权限和审计日志。
- API Key 不写入数据库，但会在当前分析请求期间经过本项目后端；请只连接你信任的自托管实例。
- 自定义 Base URL 是高级能力，部署到公网前应限制注册、配置 HTTPS、设置每日限额，并评估服务端出站访问风险。

### 5. 运行和扩展能力有限

- Docker 模式使用 MySQL；原生模式为了免 Docker 使用 SQLite，两种模式的数据文件不互通。
- 任务使用 FastAPI `BackgroundTasks`，服务重启时正在执行的任务不会自动恢复，也没有独立消息队列。
- 当前不适合多副本横向扩展；多进程/多实例部署前需要引入 Redis/Celery、对象存储和正式数据库迁移。
- 没有 GitHub Actions PR 检查、Webhook、定时扫描和团队共享仪表盘。

## 使用建议

1. 先点击“用示例仓库试一下”，确认本地服务、账号和报告导出都正常。
2. 再上传你有权审计的仓库压缩包，先查看静态候选，再决定是否填写模型 Key。
3. 不要把生产密钥、客户源码或未授权目标上传到公共演示环境。
4. 课程演示优先使用原生模式；需要 MySQL、Nginx、HTTPS 或多人访问时使用 Docker/生产编排。

## 后续改进优先级

| 优先级 | 改进项 | 目标 |
|---|---|---|
| P0 | 任务队列和断点恢复 | 服务重启不丢任务，支持取消/重试 |
| P0 | 更强的认证和密钥隔离 | HttpOnly Cookie、CSRF、防滥用和密钥轮换 |
| P1 | GitHub 仓库导入 | 只读 OAuth、分支/提交选择和增量扫描 |
| P1 | 实时进度与源码定位 | SSE/WebSocket、完整文件树、行号跳转和高亮 |
| P1 | 标准报告格式 | SARIF/PDF/CSV、CI 阻断和 Issue 回写 |
| P2 | 团队能力 | 组织、项目权限、共享报告、审计日志和 SSO |
