VulnLab 先用静态数据流把可疑代码圈出来，再让你自己的大模型逐条复核， 最后给出带 文件:行号、污染路径、分析依据和修复建议的报告。 代码只在服务端本地解压分析、永不执行；API Key 不落库、不写日志。

静态数据流 + LLM 复核 支持 OpenAI / DeepSeek / Moonshot / 通义千问 Docker Compose 一键起 Caddy 自动 HTTPS

它能做什么

不是"把模型回答贴出来"，而是一条可复核的链路：静态规则定位 → 数据流串联 → 模型确认 → 人做最终判断。

⌁数据流追踪

从 $_GET / req.query / location.search 出发，沿变量赋值追到 SQL、命令、文件、HTML 输出等危险汇点，给出完整传播路径。

✓清洗函数识别

按汇点类型区分 html / sql / shell / path / url 清洗函数：intval() 之后的 SQL 不再误报，而"HTML 转义后拼进 SQL"仍然报告。

✦用你的 Key 复核

填任意 OpenAI 兼容服务的 Base URL + Key，模型逐条给出结论、严重度、置信度与修复建议；Key 仅存浏览器并随请求发送。

▤报告可导出

任务详情按严重度分层，每条发现都能展开看代码片段与污染链路，一键导出 Markdown 报告用于提交或评审。

⛨默认安全

解压防路径穿越、拒绝软链、跳过依赖目录、限制大小与文件数；MySQL 与后端只在内网，宿主机只暴露网关；按账号限流。

⚙工程化

GitHub Actions 跑前端类型检查、后端单元测试与镜像构建；nginx 网关 + Caddy 自动证书，可直接上公网域名。

架构

一个 Compose 文件起全栈；生产环境在最前面加一层 Caddy 负责 TLS。

界面

深色安全台风格，任务进度、严重度分布与污染链路一屏可读。

部署

GitHub Pages 只能托管静态文件，跑不了 FastAPI 和 MySQL；所以代码放 GitHub，运行时用 Docker 放到任意一台机器。

本地 / 单机

# 克隆并启动
git clone https://github.com/krrb2006/llm-web-vuln-lab.git
cd llm-web-vuln-lab/web
cp .env.example .env      # 改 JWT_SECRET、数据库密码
docker compose up -d --build
# 打开 http://localhost:8080

公网 + 域名（自动 HTTPS）

# 域名已解析到本机，80/443 可访问
cp .env.prod.example .env
# 填 DOMAIN / ACME_EMAIL / 强密码
docker compose --env-file .env \
  -f docker-compose.yml -f docker-compose.prod.yml \
  up -d --build
# https://你的域名
  • 演示账号：demo@vulnlab.local / demo-vulnlab-2026（生产环境用 SEED_DEMO=false 关闭）
  • 接入模型：设置页填 Base URL + 模型名 + Key；不填 Key 也能只跑静态数据流
  • 安全边界：不执行上传代码；Key 不落库；MySQL 与后端不暴露到宿主机
